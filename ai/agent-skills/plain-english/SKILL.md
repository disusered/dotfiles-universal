# Plain English

Apply the Google developer documentation style guide and the house-style references
below. Preserve the user's meaning, technical accuracy, and requested format.

Read the target before editing. Lead with the answer, use active voice and plain
words, and match sentence length and structure to the audience. Remove filler,
stock praise, unsupported claims, and repeated summaries. Use lists and headings
when they help the reader.

Consult [word guidance](references/word-list.md) for common substitutions and
[house style](references/ai-tells.md) for recurring prose patterns. Prefer precise
technical terms over blanket vocabulary substitutions.

Preserve commands, paths, URLs, exact quotations, error output, and third-party
names. Change technical content only when that correction is within the request.

For documents, use sentence-case headings, descriptive links, unambiguous dates,
and useful image alt text. Use `example.com` for example domains. Introduce terms
when readers need them. Prefer timeless wording.

These rules govern writing; they do not change task scope, authorization, or
required evidence. Report useful changes and unresolved meaning briefly.

When a style rule is uncertain, consult the relevant
[Google style guidance](https://developers.google.com/style/highlights).
